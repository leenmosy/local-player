# Структура кода

Приложение открывается двойным кликом по `index.html`, то есть по протоколу `file://`.
Браузер **блокирует ES-модули** по `file://` (CORS: «Cross origin requests are only
supported for protocol schemes: chrome, data, http, https»), поэтому `import`/`export`
здесь использовать нельзя — это сломало бы основной способ запуска.

Вместо этого код разложен на обычные `<script>`. У классических скриптов
верхнеуровневые `let`/`const` попадают в общее глобальное лексическое окружение,
поэтому файлы видят объявления друг друга без единой строчки `import`.
Сборка не нужна: ни бандлера, ни `node_modules`, ни шага компиляции.

## Порядок подключения

Он важен и зафиксирован в `index.html`:

| Файл | Содержимое |
|---|---|
| `01-base.js` | блокировка мобильных, ссылки на DOM, константы, оверлей, тосты хранилища |
| `02-blur.js` | интервалы размытия: ввод, редактирование, применение фильтра |
| `03-storage.js` | ключи, прогресс просмотра, настройки, миграции, список «Продолжить» |
| `04-files.js` | IndexedDB, хэндлы файлов, открытие локального файла |
| `05-playlist.js` | папки, плейлист, манифесты, drag & drop |
| `06-audio.js` | синхронизация контролов, аудио-граф, панель плейлиста |
| `07-subtitles.js` | загрузка, разбор, отображение и стили субтитров |
| `08-controls.js` | настройки, скорость, картинка, хоткеи, fullscreen, буферизация |
| `09-url.js` | загрузка по ссылке: HLS, прямые ссылки, диагностика ошибок |
| `10-init.js` | редактирование названия, финальная инициализация |

## Правила, чтобы не сломать

**Объявления идут раньше использования.** Объявления функций поднимаются, и их порядок
безразличен. А вот `const`/`let` верхнего уровня — нет: обращение из кода, который
исполняется раньше объявления, упадёт с `Cannot access before initialization`. Поэтому
исполняемый код запуска держим в `10-init.js`, а объявления — выше.

**DOM-ссылки только в `01-base.js`.** Все `getElementById` собраны там, чтобы не гадать,
в каком файле объявлена переменная `video` или `stage`.

**Новый файл — новый `<script>` в `index.html`.** Порядок в списке и есть порядок
исполнения.

## Проверка после изменений

Регрессионный набор лежит в папке `tests/` — она **не** входит в репозиторий
(см. `.gitignore`), храните её отдельно вместе с архивом сборки.

```bash
cd tests && npm install && npm test
```

93 проверки в реальном браузере на реальных видеофайлах. Прогонять после каждой правки —
именно так ловятся регрессии, которые глазами не видны.
